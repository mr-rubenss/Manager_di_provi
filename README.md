# Manager_di_provi

Telegram-бот с расписанием репетиций из Google Таблицы. Бот присылает каждому
подписчику его репетиции на завтра, отвечает на `/today`, `/tomorrow`, `/week` и
предупреждает об изменениях в расписании.

Бот не работает постоянно: его по расписанию запускает GitHub Actions, он
обрабатывает накопившееся и завершается. Таблицу бот только читает и ничего в ней
не меняет.

## Как это устроено

| Workflow | Когда | Что делает |
|---|---|---|
| `.github/workflows/poll.yml` | каждые 5 минут | читает новые сообщения (`getUpdates`), отвечает, сравнивает таблицу со снимком и шлёт уведомления об изменениях; после 21:00 МСК делает рассылку на завтра, если `daily.yml` её ещё не сделал |
| `.github/workflows/daily.yml` | 21:00 МСК (18:00 UTC) | рассылает подписчикам их репетиции на завтра |

GitHub часто задерживает запуски по расписанию на 5–15 минут, поэтому бот
отвечает не мгновенно. Изменённые `state.json`, `subscribers.json` и
`schedule_snapshot.json` workflow коммитит обратно в репозиторий с пометкой
`[skip ci]`. Оба workflow в одной группе `concurrency` и не пересекаются.

**Рассылка на завтра** уходит в первый запуск после 21:00 по Москве, один раз за
вечер. Если репетиций у человека нет, сообщение не отправляется:

```
РАСПИСАНИЕ РЕПЕТИЦИЙ 12.11.26:
11:00-12:00 110 в тени (задействованы: Миша П, Лиза; аудитория 301)
12:00-13:00 Альба (задействованы: Миша К, Соня; аудитория 309)
```

**Уведомления об изменениях.** Бот сравнивает записи с сегодняшней даты и позже
с прошлым снимком. Если запись добавили, удалили или изменили время, название,
участников или аудиторию, уведомление получают и старый, и новый состав, одним
сообщением на человека:

```
ИЗМЕНЕНИЕ В РАСПИСАНИИ 12.11.26:
было: 12:00-13:00 Альба (задействованы: Соня, Миша К; аудитория 309)
стало: 12:30-13:30 Альба (задействованы: Соня, Миша К; аудитория 309)
```

У новой записи будет `было: —`, у удалённой `стало: отменено`. При первом
запуске бот только создаёт снимок. Если таблица не скачалась или пришла пустой,
сравнения не будет.

**Команды бота:** `/start` (предупреждение, кнопка «Согласен», затем выбор имени),
`/today`, `/tomorrow`, `/week` (7 дней с сегодняшнего), `/stop`.

## Запуск в GitHub Actions

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи токен.
2. Добавь токен в секрет репозитория: **Settings → Secrets and variables → Actions →
   New repository secret**, имя `TELEGRAM_BOT_TOKEN`. В код, файлы и логи токен
   не попадает. Ошибки сети бот очищает от адреса с токеном.
3. **Settings → Actions → General → Workflow permissions → Read and write
   permissions**, иначе бот не сможет коммитить своё состояние.
4. Слей ветку в ветку по умолчанию (обычно `main`). GitHub запускает workflow по
   расписанию только оттуда.
5. Проверь первый запуск: **Actions → Bot poll → Run workflow**. Затем напиши
   боту `/start`.

Ручной запуск рассылки: **Actions → Bot daily → Run workflow**. Флажок `force`
отправляет рассылку сразу, даже до 21:00 и повторно.

> GitHub отключает workflow по расписанию, если в репозитории 60 дней не было
> коммитов. Бот коммитит только когда что-то изменилось. Если в тихий период
> workflow выключится, включи его заново на вкладке Actions.

## Локальный запуск и проверка без отправки сообщений

Нужен Python 3.10+:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -t .     # все тесты, сеть и токен не нужны
```

Проверять бота лучше в таком порядке, от безопасного к реальному:

**1. Тесты.** Покрывают парсер на кривых данных, имена, группы, рассылку,
уведомления и то, что токен не попадает в ошибки. Telegram в них подменён, сеть
не нужна.

**2. Что получит конкретный человек.** Команда скачивает реальную таблицу, но
ничего не отправляет:

```bash
python bot.py preview Соня            # репетиции на завтра
python bot.py preview Соня 12.11.26   # на конкретную дату
```

**3. Проверка имён.** Неоднозначные имена («Миша» без буквы), непонятные слова и
люди с полом «?»:

```bash
python bot.py check_names
```

**4. Сухой прогон всего бота (`--dry-run`).** Бот работает с реальной таблицей,
но Telegram не вызывается. Сообщения и кнопки печатаются в консоль, а
`state.json`, `subscribers.json` и `schedule_snapshot.json` меняются только во
временной копии. Токен не нужен:

```bash
# полный сценарий: /start → «Согласен» → выбор «Соня» → /week → /stop
python bot.py run --dry-run --updates examples/dry_run_updates.json

# рассылка на завтра так, будто сейчас 21:05 по Москве
python bot.py run --dry-run --now "2026-11-11 21:05"
```

В `examples/dry_run_updates.json` лежат «входящие сообщения» в формате Telegram.
Их можно править: другие chat_id, имена (`"data": "n:софа"`), команды.

**5. Тестовый бот.** Чтобы проверить настоящий Telegram, создай у @BotFather
второго бота и запусти с его токеном в отдельной копии репозитория (форк или
клон):

```bash
TELEGRAM_BOT_TOKEN=<токен тестового бота> python bot.py poll
```

> Не запускай локально `poll` с токеном **основного** бота. Он заберёт сообщения
> из очереди Telegram и запишет `offset` в локальный `state.json`. Бот в GitHub
> Actions этих сообщений уже не увидит, а его состояние разойдётся с твоим.

Все режимы описаны в `python bot.py --help`.

## Смена рабочей вкладки таблицы

Сейчас бот читает вкладку **«Лист1»** таблицы
`1kVfvZjTg28-gBQXUATRMetdhLhUGdL0dg4oxJSJ2fdw`. Вкладка ищется по названию,
номер (`gid`) знать не нужно.

**Способ без правки кода.** В **Settings → Secrets and variables → Actions →
Variables** создай переменную:

* `SCHEDULE_SHEET_NAME` — название вкладки, как на ярлычке внизу таблицы,
  например `Лист 2`;
* `SCHEDULE_SPREADSHEET_ID` — если меняется сама таблица: часть ссылки между
  `/d/` и `/edit`.

Пустая переменная означает значение по умолчанию. Локально это обычные
переменные окружения:

```bash
SCHEDULE_SHEET_NAME="Лист 2" python bot.py preview Соня
```

**Способ через код.** Поменяй `SHEET_NAME` или `SPREADSHEET_ID` в начале
`schedule_parser.py`.

Что важно при смене:

* Таблица должна быть открыта на чтение по ссылке. Вкладка должна иметь ту же
  структуру: в строке 1 день недели и дата (`дд.мм.гг`), в строке 2 аудитории над
  блоками по 3 столбца, в строке 3 заголовки, с 4-й строки данные.
* Ложных уведомлений «всё отменено» не будет. В снимке записано, с какой таблицы и
  вкладки он сделан. Если источник поменялся, первый запуск просто создаст новый
  снимок и ничего не разошлёт.
* Перед сменой проверь новую вкладку локально:
  `SCHEDULE_SHEET_NAME="..." python bot.py check_names`.

## Какие данные хранит бот и как их удалить

Репозиторий публичный. Всё, что лежит в файлах ниже, видно любому.

| Файл | Что там | Откуда |
|---|---|---|
| `subscribers.json` | **Telegram chat_id → имя из расписания** | от пользователя, только после «Согласен» и выбора имени |
| `state.json` | номер последнего обработанного сообщения и дата последней рассылки | бот; личных данных нет |
| `schedule_snapshot.json` | копия записей расписания с сегодняшней даты: имена, время, аудитории | из таблицы, которая и так открыта по ссылке |
| `people.json` | имена из таблицы и пол («ж»/«м»/«?») | заполняешь ты, вручную |
| `aliases.json` | варианты имён («Лиза» → «Соня») | заполняешь ты, вручную |

chat_id личного чата совпадает с Telegram ID пользователя. По нему нельзя
написать человеку без бота, но его можно связать с аккаунтом. Текст сообщений
бот не хранит. В логах GitHub Actions только счётчики («отправлено 3»), без
chat_id и имён.

**До согласия бот ничего не сохраняет.** `/start` показывает предупреждение, а
запись появляется, только когда человек нажал «Согласен» и выбрал имя.

**Удаление: команда `/stop`.** Бот удаляет запись из `subscribers.json`, и
изменение коммитится при ближайшем запуске poll (обычно через 5–15 минут). Если
человек заблокировал бота, его запись удаляется при следующей попытке отправить
ему сообщение.

**Важно: `/stop` не стирает историю git.** Прошлые версии `subscribers.json`
остаются в истории коммитов публичного репозитория. Полностью убрать chat_id
можно только переписав историю (`git filter-repo`) и сделав force push. Даже
тогда данные могут остаться в форках и кэшах. Если это критично, держи
репозиторий с состоянием бота приватным.

`/stop` удаляет только связку «chat_id → имя». Имя в таблице, `people.json` и
снимке расписания остаётся, потому что оно взято из самой таблицы, а не от
пользователя.

## Имена и группы

* **Сравнение имён.** Имя сравнивается только целиком, без учёта регистра,
  `ё == е`, точка после инициала не важна («Василиса К.» == «Василиса К»).
  Варианты имён сводятся к основному через `aliases.json`.
* **Кто считается человеком.** Только имя из `people.json`. Слово, которое не имя и
  не группа, считается непонятным: рассылки по нему нет, его показывает
  `check_names`. Новичка нужно добавить в `people.json`, иначе он не появится в
  кнопках регистрации.
* **Группы:**
  * всем подписчикам: «весь курс», «все», «хор»;
  * только девушкам: «все девушки», «девушки», «хор женщины», «хор (женщины)»;
  * только парням: «все парни», «парни», «хор мужчины», «хор (мужчины)».

  Пол берётся из `people.json`. При «?» рассылка по полу не идёт, только «всем».
  В строке расписания группа выводится как в таблице.
* **Разные люди.** «Миша К» и «Миша П», «Василиса К.» и «Василиса О» (они же
  «Вася К» и «Вася О»), «Софа» и «Соня»/«Лиза» — разные люди. Если
  `aliases.json` попытается их объединить, бот остановится с ошибкой.
* **Имя без буквы фамилии.** «Миша», когда есть «Миша К» и «Миша П», бот не
  угадывает и показывает в `check_names`.
* **Параллельные репетиции.** Записи в одно время и в одной аудитории — это норма,
  они выводятся отдельными строками.

Как парсер понимает кривое время: «10-11» → 10:00-11:00, «14:30 - 15:30»,
«15:30- 16:30», «19:00–20:00», «16:15-16-35» → 16:15-16:35, «16-35» → 16:35.
Если время нельзя понять однозначно («11-10», «10:60», два интервала в ячейке),
бот показывает текст ячейки как есть. Участники делятся по запятым, «;»,
переносам строк и союзу «и». Пометки в скобках отделяются от имени.

## Файлы

| Файл | Назначение |
|---|---|
| `schedule_parser.py` | скачивание вкладки как CSV и разбор в записи |
| `names.py` | сравнение имён, алиасы, группы, пол |
| `changes.py` | снимок расписания и поиск изменений |
| `bot.py` | логика бота и режимы запуска |
| `storage.py` | чтение и запись JSON |
| `tests/` | тесты (`python -m unittest discover -s tests -t .`) |
| `examples/dry_run_updates.json` | входящие сообщения для сухого прогона |
